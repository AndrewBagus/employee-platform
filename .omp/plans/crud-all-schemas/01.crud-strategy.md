# All-Tables CRUD — Implementation Strategy

## 1. Current Pattern Recap (Companies)

Per entity:
| File | What |
|------|------|
| `src/dtos/<entity>.dto.ts` | Zod create/update schemas + `infer` types + response type |
| `src/repositories/<entity>/<entity>.repository.interface.ts` | Interface (findAll, findById, create, update, softDelete) |
| `src/repositories/<entity>/<entity>.repository.ts` | `@injectable()` class with Drizzle queries |
| `src/services/<entity>/<entity>.service.interface.ts` | Interface (findAll, findById, create, update, delete) |
| `src/services/<entity>/<entity>.service.ts` | `@injectable()` class, Zod validation |
| `src/controllers/<entity>.controller.ts` | Hono sub-app (5 routes), lazily resolves service from container |
| `src/cores/types.ts` | TYPES symbol entry |
| `src/cores/container.ts` | Container binding |

Test files mirror the layer structure:
| Test | Strategy |
|------|----------|
| Repository | SQL shape assertions (`.toSQL()`), interface contract |
| Service | Mock repo, verify validation + delegation |
| Controller | Container rebind + dynamic import, verify HTTP codes + body |

**~90± of the code is boilerplate — only the DTO fields, table reference, entity name, and FK structure differ per entity.**

## 2. Proposed Architecture: Shared Abstractions

### 2.1 Base Repository (`src/repositories/base.repository.ts`)

```typescript
import { injectable, inject } from "inversify";
import { NodePgDatabase } from "drizzle-orm/node-postgres";
import { and, eq, sql } from "drizzle-orm";
import type { PgTableWithColumns } from "drizzle-orm/pg-core";
import { TYPES } from "@cores/types";

@injectable()
export abstract class BaseRepository<
  TTable extends PgTableWithColumns<any>,
  TResponse extends Record<string, any>,
  TCreate extends Record<string, any>,
  TUpdate extends Record<string, any>,
> {
  constructor(
    @inject(TYPES.Database) protected readonly db: NodePgDatabase,
    protected readonly table: TTable,
  ) {}

  async findAll(): Promise<TResponse[]> {
    const rows = await this.db
      .select()
      .from(this.table)
      .where(eq((this.table as any).stsActive, true))
      .orderBy((this.table as any).name);
    return rows as TResponse[];
  }

  async findById(id: string): Promise<TResponse | null> {
    const rows = await this.db
      .select()
      .from(this.table)
      .where(
        and(eq((this.table as any).id, id), eq((this.table as any).stsActive, true)),
      )
      .limit(1);
    return (rows[0] as TResponse) ?? null;
  }

  async create(data: TCreate): Promise<TResponse> {
    const rows = await this.db
      .insert(this.table)
      .values(data as any)
      .returning();
    return rows[0] as TResponse;
  }

  async update(id: string, data: TUpdate): Promise<TResponse | null> {
    const updateData: Record<string, unknown> = {};
    for (const [key, value] of Object.entries(data as any)) {
      if (value !== undefined) updateData[key] = value;
    }
    const rows = await this.db
      .update(this.table)
      .set(updateData)
      .where(eq((this.table as any).id, id))
      .returning();
    return (rows[0] as TResponse) ?? null;
  }

  async softDelete(id: string): Promise<void> {
    await this.db
      .update(this.table)
      .set({
        stsActive: false,
        deletedAt: sql`now()`,
      })
      .where(eq((this.table as any).id, id));
  }
}
```

**Trade-off**: `(this.table as any).stsActive` — weak typing inside the base. But the concrete subclass is fully typed.

### 2.2 Base Service (`src/services/base.service.ts`)

```typescript
import { injectable } from "inversify";
import { z } from "zod";
import { ValidationError, NotFoundError } from "@cores/errors";

@injectable()
export abstract class BaseService<
  TResponse extends Record<string, any>,
  TCreate extends Record<string, any>,
  TUpdate extends Record<string, any>,
  TRepo extends { findAll(): Promise<TResponse[]>; findById(id: string): Promise<TResponse | null>; create(data: TCreate): Promise<TResponse>; update(id: string, data: TUpdate): Promise<TResponse | null>; softDelete(id: string): Promise<void>; },
> {
  constructor(
    protected readonly repository: TRepo,
    protected readonly createSchema: z.ZodSchema<TCreate>,
    protected readonly updateSchema: z.ZodSchema<TUpdate>,
    protected readonly entityName: string,
  ) {}

  async findAll(): Promise<TResponse[]> {
    return this.repository.findAll();
  }

  async findById(id: string): Promise<TResponse | null> {
    return this.repository.findById(id);
  }

  async create(data: unknown): Promise<TResponse> {
    try {
      const validated = this.createSchema.parse(data);
      return this.repository.create(validated);
    } catch (err) {
      if (err instanceof z.ZodError) {
        throw new ValidationError(err.issues.map((i) => i.message).join("; "));
      }
      throw err;
    }
  }

  async update(id: string, data: unknown): Promise<TResponse> {
    if (!id || typeof id !== "string") {
      throw new ValidationError("id is required");
    }

    const existing = await this.repository.findById(id);
    if (!existing) {
      throw new NotFoundError(`${this.entityName} with id ${id} not found`);
    }

    try {
      const validated = this.updateSchema.parse(data);
      const updated = await this.repository.update(id, validated);
      if (!updated) {
        throw new NotFoundError(`${this.entityName} with id ${id} not found`);
      }
      return updated;
    } catch (err) {
      if (err instanceof z.ZodError) {
        throw new ValidationError(err.issues.map((i) => i.message).join("; "));
      }
      throw err;
    }
  }

  async delete(id: string): Promise<void> {
    if (!id || typeof id !== "string") {
      throw new ValidationError("id is required");
    }

    const existing = await this.repository.findById(id);
    if (!existing) {
      throw new NotFoundError(`${this.entityName} with id ${id} not found`);
    }

    await this.repository.softDelete(id);
  }
}
```

### 2.3 Controller Factory (`src/controllers/base.controller.ts`)

```typescript
import { Hono } from "hono";
import { container } from "@cores/container";
import { AppError } from "@cores/errors";

type ServiceActions = {
  findAll(): Promise<any[]>;
  findById(id: string): Promise<any | null>;
  create(data: unknown): Promise<any>;
  update(id: string, data: unknown): Promise<any>;
  delete(id: string): Promise<void>;
};

export function createController(
  serviceKey: symbol,
  entityLabel: string,       // lowercase singular e.g. "country"
  entityLabelPlural: string, // lowercase plural  e.g. "countries"
): Hono {
  const ctrl = new Hono();
  const getService = () => container.get<ServiceActions>(serviceKey);

  ctrl.get("/", async (c) => {
    const items = await getService().findAll();
    return c.json({
      success: true,
      data: items,
      message: `${entityLabelPlural} retrieved successfully`,
    });
  });

  ctrl.get("/:id", async (c) => {
    try {
      const id = c.req.param("id");
      const item = await getService().findById(id);
      if (!item) {
        return c.json({ success: false, data: null, message: `${entityLabel} not found` }, 404);
      }
      return c.json({ success: true, data: item, message: `${entityLabel} retrieved successfully` });
    } catch (error) {
      if (error instanceof AppError) {
        return c.json({ success: false, data: null, message: error.message }, error.statusCode);
      }
      throw error;
    }
  });

  ctrl.post("/", async (c) => {
    try {
      const body = await c.req.json();
      const item = await getService().create(body);
      return c.json({ success: true, data: item, message: `${entityLabel} created successfully` }, 201);
    } catch (error) {
      if (error instanceof AppError) {
        return c.json({ success: false, data: null, message: error.message }, error.statusCode);
      }
      throw error;
    }
  });

  ctrl.put("/:id", async (c) => {
    try {
      const id = c.req.param("id");
      const body = await c.req.json();
      const item = await getService().update(id, body);
      return c.json({ success: true, data: item, message: `${entityLabel} updated successfully` });
    } catch (error) {
      if (error instanceof AppError) {
        return c.json({ success: false, data: null, message: error.message }, error.statusCode);
      }
      throw error;
    }
  });

  ctrl.delete("/:id", async (c) => {
    try {
      const id = c.req.param("id");
      await getService().delete(id);
      return c.json({ success: true, data: null, message: `${entityLabel} deleted successfully` });
    } catch (error) {
      if (error instanceof AppError) {
        return c.json({ success: false, data: null, message: error.message }, error.statusCode);
      }
      throw error;
    }
  });

  return ctrl;
}
```

export interface CountryResponseDto {

## 3. Code Generation for DTOs

DTOs are the most tedious and error-prone part. The drizzle schema files already define every column with its type. We can extract:

- Column name (camelCase from Drizzle column object)
- Column type (string → `z.string()`, boolean → `z.boolean()`, date → `z.coerce.date()`, enum → `z.enum()`, numeric → `z.coerce.number()`)
- Not-null constraint → `.min(1)` or required
- Default value → optional in create

**Approach**: A standalone script (`scripts/generate-dtos.ts`) that:
1. Reads each exported `pgTable` definition via static analysis (regex/text parse since Drizzle schema files are simple)
2. Extracts column info: `name: varchar({ length: 100 })`, `name: boolean().default(false)`, `name: pgEnumType()`
3. Generates:
   - Response interface (all columns, all nullable — matches DB row)
   - Create schema (writable columns only; not id, stsActive, createdAt, createdBy, etc.)
   - Update schema (all writable columns optional)
4. Outputs to `src/dtos/<entity>.dto.ts`

**Schema file parse patterns** (Drizzle schemas are simple enough for lightweight regex):
```
Column pattern:  columnName: columnType(args).chain()
Skip columns:    id, stsActive, createdAt, createdBy, updatedAt, updatedBy, deletedAt, ...defaultColumn
FK references:   uuid().references(() => otherTable.id, { ... }).notNull()  →  z.string().min(1)
pgEnum columns:  columnName: enumType()                                     →  z.enum([...])
varchar:         varchar({ length: N })                                     →  z.string()
text:            text()                                                     →  z.string()
boolean:         boolean().default(val)                                    →  z.boolean().optional()
numeric:         numeric({ precision, scale })                             →  z.coerce.number()
date:            date()                                                     →  z.coerce.date().optional()  (or z.string() for plain dates)
smallint:        smallint()                                                 →  z.number().int()
```

**Script location**: `scripts/generate-dtos.ts` — run with `bun run scripts/generate-dtos.ts`

**Output per table**: one `src/dtos/<table>.dto.ts` file.

## 4. Implementation Order (A → B → C → D)

### Phase 0: Infrastructure (1 step)
| Step | Files | Change |
|------|-------|--------|
| 0.1 | `src/repositories/base.repository.ts` | Create generic base class |
| 0.2 | `src/services/base.service.ts` | Create generic base class |
| 0.3 | `src/controllers/base.controller.ts` | Create controller factory |
| 0.4 | `scripts/generate-dtos.ts` | DTO codegen script |

### Phase A: Group A — Simple master tables (5 entities)
countries · religion · grades · costCenters · projects

| Step | Entity | Generated DTO | Files changed |
|------|--------|---------------|---------------|
| A.1 | — | Run codegen for Group A | 5 DTO files |
| A.2 | countries | Repo, service, controller, DI | types.ts +1, container.ts +2, repo*2, svc*2, ctrl*1 |
| A.3 | religion | Same pattern | types +1, container +2, repo*2, svc*2, ctrl*1 |
| A.4 | grades | Same | ... |
| A.5 | costCenters | Same | ... |
| A.6 | projects | Same | ... |

These are fully independent — can be done in a single batch via subagents.

### Phase B: Group B — FK to companies/countries (10 entities)
departments · positions · allowances · warningGrades · warnings
trainingTypes · trainings · trainingSchedules · workingZones

Additional consideration: FK validation (when creating an entity, the referenced FK must exist). This can be:
- **Skip FK validation** in Phase B (defer to DB constraint since they're `restrict` on delete). The DB will reject invalid FKs at INSERT time.
- **Add FK validation** as an enhancement in a follow-up. Phase B is large as-is; keeping it simple saves effort.

If FK validation is desired, add it as a custom override in the service's `create` method for entities with FKs, or as a base service hook.

Same file pattern as Phase A. All independent — batch.

### Phase C: Group C — Employees (complex, 1 entity)

Special considerations:
- 25 columns → DTO will be large but still code-generated
- 4 enums → Zod `.nativeEnum()` from the Drizzle enum values
- `supervisorId` (self-ref FK) → `z.string().optional()` in create, not validated at service level (defer to DB)
- Required fields: `companyId`, `departmentId`, `positionId`, `fingerId`, `firstName`, `email`
- Many optional/nullable fields

Suggested approach:
- `CreateEmployeeSchema` makes the 6 required fields mandatory, everything else optional
- `UpdateEmployeeSchema` makes everything optional
- Service overrides `findAll` if pagination is needed (out of scope for MVP)
- Test file will be larger but same structure

### Phase D: Group D — Employee sub-tables (9 entities)
employeeAddresses · employeeContracts · employeeContractAdvisors
employeeLeaveAdvisors · employeeMcus · employeeProjects (composite PK)
employeeTrainings · employeeWarnings · employeeWorkZones

**Composite PK case (employeeProjects)**: The base repository assumes `id` UUID PK. `employeeProjects` has no `id` column — it uses `(employeeId, projectId)` as composite PK. Two options:
1. Add `id` column to the table (schema migration) — simpler for codegen uniformity
2. Custom repository that overrides `findById`, `update` with composite key

**Recommendation**: Option 1 (add `id` column) if schema changes are acceptable. Option 2 if not. Either way it's a single special case.

## 5. Test Strategy (Same Pattern × 24)

### Repository tests
Per entity: 6 tests (same as companies)
- findAll SQL shape
- findById SQL shape
- findById non-existent
- create SQL shape
- update SQL shape
- softDelete SQL shape

**Could be reduced** via a shared test factory:
```typescript
// tests/helpers/repo-test-factory.ts
export function testRepository<T>(
  name: string,
  RepoClass: new (...args: any[]) => T,
  table: any,
  createSample: () => Record<string, unknown>,
) {
  describe(`${name}Repository`, () => {
    // ... shared tests
  });
}
```

But shared test factories can be fragile. The plan recommends **shared test factory functions** for the ~20 simple entities, with per-file override capacity for edge cases.

### Service tests
Per entity: 9 tests (same as companies)
- findAll delegates
- findById delegates
- create validates required
- create validates enums (where applicable)
- create delegates valid
- update validates id
- update checks existence
- update delegates valid
- delete checks existence
- delete delegates

### Controller tests
Per entity: 9 tests (same as companies)
- GET /
- GET /:id 200
- GET /:id 404
- POST / 201
- POST / 400 validation
- PUT /:id 200
- PUT /:id 404
- DELETE /:id 200
- DELETE /:id 404

**Test count**: 24 entities × 24 tests = ~576 tests total.

This is the biggest time sink. To compress:
1. Create test factory functions for repo/service/controller layers
2. Each entity's test file is a 10-line call to the factory + any entity-specific overrides
3. Run ALL tests at the end — they are unit tests (no DB), so they run in <1s per entity

## 7. Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| TypeScript generics get unwieldy | The generic parameters are <4 (Table, Response, Create, Update). If they become too complex, fall back to simple per-entity classes copying the base pattern. |
| `employeeProjects` composite PK | Handle as a special case — either add `id` column or write a custom repository override. |
| Zod schema generation misses edge cases | Codegen handles 90+% of columns correctly. Review each generated DTO before committing; manual corrections take seconds per file. |
| Test factory abstraction too clever | If the test factory becomes cryptic, write per-entity tests with copy-paste. Tests are simple and repetitive by design. |
| FK validation absent for Group B | MVP relies on DB referential integrity (RESTRICT). Add Zod checks in a follow-up if needed. |
