# Companies CRUD Endpoints — Implementation Plan

## Overview

Extend the existing `GET /companies` (list-all) with four new endpoints on the companies Hono sub-app, following the existing patterns: Inversify DI, Drizzle ORM, manual validation, `@` path aliases, and consistent response envelope.

All existing files live under the flat `src/` structure:
- `src/controllers/company.controller.ts`
- `src/services/company/company.service.ts` + `.interface.ts`
- `src/repositories/company/company.repository.ts` + `.interface.ts`
- `src/dtos/company.dto.ts`
- `src/cores/container.ts` + `types.ts`

## 1. DTOs to Add

### `src/dtos/company.dto.ts` — Append to existing file

Add two input DTO types alongside the existing `CompanyResponseDto`:

```typescript
// ── New: Input DTOs ──

export interface CreateCompanyDto {
  name: string;
  type: "GROUP" | "CLIENT" | "SUBCON";
  countryId: string;
  nameShort?: string;
  haveWorkerEmployee?: boolean;
  isLdap?: boolean;
}

export interface UpdateCompanyDto {
  name?: string;
  nameShort?: string;
  type?: "GROUP" | "CLIENT" | "SUBCON";
  countryId?: string;
  haveWorkerEmployee?: boolean;
  isLdap?: boolean;
}
```

**Design notes:**
- `CreateCompanyDto` makes `name`, `type`, `countryId` required (the three fields validated as mandatory). All other writable fields are optional.
- `UpdateCompanyDto` makes everything optional — PUT is a partial update. Omitted fields are not touched.
- `haveWorkerEmployee` and `isLdap` are included as writable because they have DB defaults; clients can omit them and the DB default kicks in.
- `CompanyResponseDto` needs no changes — it already mirrors the full DB row shape (id, audit fields, etc.).

### Response Envelope (already documented, no file needed)

```typescript
interface ApiResponse<T> {
  success: boolean;
  data: T | null;
  message: string;
}
```

Used inline in every controller handler via `c.json(...)`.

### `src/repositories/company/company.repository.ts` — Add implementations

**Imports needed at top:**
```typescript
import { and, eq, sql } from "drizzle-orm";
import type { CreateCompanyDto, UpdateCompanyDto } from "@dtos/company.dto";
```

**`findById`** — Select by id AND stsActive (soft-deleted records are invisible):

```typescript
async findById(id: string): Promise<CompanyResponseDto | null> {
  const rows = await this.db
    .select()
    .from(companies)
    .where(and(eq(companies.id, id), eq(companies.stsActive, true)))
    .limit(1);

  return (rows[0] as CompanyResponseDto) ?? null;
}
```

**`create`** — Insert and return the created row:

```typescript
async create(data: CreateCompanyDto): Promise<CompanyResponseDto> {
  const rows = await this.db
    .insert(companies)
    .values({
      name: data.name,
      nameShort: data.nameShort ?? null,
      type: data.type,
      countryId: data.countryId,
      haveWorkerEmployee: data.haveWorkerEmployee ?? false,
      isLdap: data.isLdap ?? false,
    })
    .returning();

  return rows[0] as CompanyResponseDto;
}
```

Note: `haveWorkerEmployee` / `isLdap` defaults match the DB schema defaults (`false`). The `.values()` call explicitly sets them so the return is predictable. `createdBy` and `updatedBy` are nullable and not set by this endpoint (currently no auth context) — they default to `null`.

**`update`** — Partial update: Drizzle `set` ignores `undefined` values. Spread the input so only provided fields are applied:

```typescript
async update(id: string, data: UpdateCompanyDto): Promise<CompanyResponseDto | null> {
  // Filter to only fields that are actually provided (not undefined)
  const updateData: Record<string, unknown> = {};
  if (data.name !== undefined) updateData.name = data.name;
  if (data.nameShort !== undefined) updateData.nameShort = data.nameShort;
  if (data.type !== undefined) updateData.type = data.type;
  if (data.countryId !== undefined) updateData.countryId = data.countryId;
  if (data.haveWorkerEmployee !== undefined) updateData.haveWorkerEmployee = data.haveWorkerEmployee;
  if (data.isLdap !== undefined) updateData.isLdap = data.isLdap;

  const rows = await this.db
    .update(companies)
    .set(updateData)
    .where(eq(companies.id, id))
    .returning();

  return (rows[0] as CompanyResponseDto) ?? null;
}
```

**Why the manual filter?** Drizzle `.set()` accepts a partial row object. If we pass `{ name: "X", nameShort: undefined }`, Drizzle may try to set `name_short = NULL`. The explicit filter ensures only provided keys reach the query.

**`softDelete`** — Set stsActive = false, deletedAt = now():

```typescript
async softDelete(id: string): Promise<void> {
  await this.db
    .update(companies)
    .set({
      stsActive: false,
      deletedAt: sql`now()`,
    })
    .where(eq(companies.id, id));
}
```

Note: The `updatedAt` column has a `$onUpdate` trigger via `defaultColumn`, so it auto-updates on any `UPDATE` query. No need to set it manually.

**SQL generated (softDelete):**
```sql
UPDATE "companies"
SET "sts_active" = false, "deleted_at" = now()
WHERE "id" = $1;
```

### `src/services/company/company.service.ts` — Add implementations

**Validation helper** (defined inside the service, or as a module-level utility):

```typescript
function validateCreateInput(data: Record<string, unknown>): asserts data is CreateCompanyDto {
  const errors: string[] = [];

  if (!data.name || typeof data.name !== "string" || data.name.trim().length === 0) {
    errors.push("name is required and must be a non-empty string");
  }

  if (!data.type || !["GROUP", "CLIENT", "SUBCON"].includes(data.type as string)) {
    errors.push("type is required and must be one of: GROUP, CLIENT, SUBCON");
  }

  if (!data.countryId || typeof data.countryId !== "string") {
    errors.push("countryId is required and must be a string (UUID)");
  }

  if (errors.length > 0) {
    throw new ValidationError(errors.join("; "));
  }
}
```

**`findById`:**

```typescript
async findById(id: string): Promise<CompanyResponseDto | null> {
  return this.repository.findById(id);
}
```

Pass-through — the repository handles the `stsActive` filter.

**`create`:**

```typescript
async create(data: CreateCompanyDto): Promise<CompanyResponseDto> {
  validateCreateInput(data);
  return this.repository.create(data);
}
```

**`update`:**

```typescript
async update(id: string, data: UpdateCompanyDto): Promise<CompanyResponseDto> {
  // Validate id format
  if (!id || typeof id !== "string") {
    throw new ValidationError("id is required");
  }

  // Ensure the company exists before updating
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundError(`Company with id ${id} not found`);
  }

  const updated = await this.repository.update(id, data);
  // update() returns null only if the WHERE matched zero rows
  // (already guarded by the findById above, but belt-and-suspenders)
  if (!updated) {
    throw new NotFoundError(`Company with id ${id} not found`);
  }

  return updated;
}
```

**`delete` (soft):**

```typescript
async delete(id: string): Promise<void> {
  if (!id || typeof id !== "string") {
    throw new ValidationError("id is required");
  }

  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundError(`Company with id ${id} not found`);
  }

  await this.repository.softDelete(id);
}
```

**Error classes** (defined in a shared location, e.g. `src/cores/errors.ts`):

  }
}

## 4. Controller / Routes

### `src/controllers/company.controller.ts` — Full file after changes

The Hono sub-app routes:

```typescript
import { Hono } from "hono";
import { container } from "@cores/container";
import { TYPES } from "@cores/types";
import type { CompanyServiceInterface } from "@services/company/company.service.interface";
import { AppError } from "@cores/errors";

const companyController = new Hono();

const service = container.get<CompanyServiceInterface>(TYPES.CompanyServiceInterface);

// ── Existing ──
companyController.get("/", async (c) => {
  const companies = await service.findAll();
  return c.json({
    success: true,
    data: companies,
    message: "Companies retrieved successfully",
  });
});

// ── New: GET /companies/:id ──
companyController.get("/:id", async (c) => {
  try {
    const id = c.req.param("id");
    const company = await service.findById(id);

    if (!company) {
      return c.json({
        success: false,
        data: null,
        message: "Company not found",
      }, 404);
    }

    return c.json({
      success: true,
      data: company,
      message: "Company retrieved successfully",
    });
  } catch (error) {
    if (error instanceof AppError) {
      return c.json({
        success: false,
        data: null,
        message: error.message,
      }, error.statusCode);
    }
    throw error;
  }
});

// ── New: POST /companies ──
companyController.post("/", async (c) => {
  try {
    const body = await c.req.json();
    const company = await service.create(body);

    return c.json({
      success: true,
      data: company,
      message: "Company created successfully",
    }, 201);
  } catch (error) {
    if (error instanceof AppError) {
      return c.json({
        success: false,
        data: null,
        message: error.message,
      }, error.statusCode);
    }
    throw error;
  }
});

// ── New: PUT /companies/:id ──
companyController.put("/:id", async (c) => {
  try {
    const id = c.req.param("id");
    const body = await c.req.json();
    const company = await service.update(id, body);

    return c.json({
      success: true,
      data: company,
      message: "Company updated successfully",
    });
  } catch (error) {
    if (error instanceof AppError) {
      return c.json({
        success: false,
        data: null,
        message: error.message,
      }, error.statusCode);
    }
    throw error;
  }
});

// ── New: DELETE /companies/:id (soft delete) ──
companyController.delete("/:id", async (c) => {
  try {
    const id = c.req.param("id");
    await service.delete(id);

    return c.json({
      success: true,
      data: null,
      message: "Company deleted successfully",
    });
  } catch (error) {
    if (error instanceof AppError) {
      return c.json({
        success: false,
        data: null,
        message: error.message,
      }, error.statusCode);
    }
    throw error;
  }
});

export default companyController;
```

## 6. Error Handling Architecture

```
Controller (try/catch)
  │
  ├─ Service throws ValidationError (400)
  │    → Controller catches AppError → c.json({ success: false, data: null, message }, 400)
  │
  ├─ Service throws NotFoundError (404)
  │    → Controller catches AppError → c.json({ success: false, data: null, message }, 404)
  │
  └─ Unexpected error (e.g. DB connection failure)
       → Controller lets it propagate → Hono default error middleware returns 500
```

The `AppError` hierarchy (defined in `src/cores/errors.ts`) carries the HTTP status code on the error instance, so the controller catch clause is a single `instanceof AppError` check.

All endpoints that can return 404 also have an explicit null-check path in the controller (for the `findById` pass-through where the service returns `null` rather than throwing).

## 9. Key Design Decisions

1. **Soft-deleted records are invisible to read operations.** Both `findAll` and `findById` filter `stsActive = true`. Soft-deleted records are not accessible via the API — they live for audit/history.

2. **DELETE returns `data: null`.** The soft delete has no meaningful response body beyond the success message. The envelope convention is followed consistently.

3. **PUT is a partial update.** Not a full replacement. Omitted fields are not reset to defaults. This matches the `UpdateCompanyDto` where all fields are optional.

4. **No auth context for audit fields.** `createdBy` / `updatedBy` are left as `null` since the current scope has no authentication. This is a future concern.

5. **Error classes are lightweight.** No dependency injection — they are plain `Error` subclasses exported from a utility module. The controller catches `AppError` and maps `statusCode` to the HTTP response.
