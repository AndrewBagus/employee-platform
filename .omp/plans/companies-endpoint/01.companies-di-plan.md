# GET /companies — DI Architecture Plan

## Directory structure

```
src/
├── index.ts                          # Entry point — container-aware Hono app bootstrap
├── di/
│   ├── PLAN.md                       # This file
│   ├── container.ts                  # Build & export Inversify container, wire everything
│   └── identifiers.ts                # Inversify symbol constants for all DI bindings
└── modules/
    └── companies/
        ├── interfaces/
        │   ├── ICompanyRepository.ts # Repository contract
        │   └── ICompanyService.ts    # Service contract
        ├── dtos/
        │   └── company.dto.ts        # CompanyResponseDto type
        ├── company.repository.ts     # Implements ICompanyRepository — Drizzle queries
        ├── company.service.ts        # Implements ICompanyService — business logic, entity→DTO mapping
        ├── company.controller.ts     # Hono handler class — parse request, return JSON
        └── company.routes.ts         # Registers company routes on the Hono app
```

## Step 1 — Install dependencies

```
bun add inversify reflect-metadata
```

No type packages needed — `inversify` ships its own types. `reflect-metadata` is a runtime polyfill.

---

## Step 2 — tsconfig.json decorator support

Add to `compilerOptions`:

```json
{
  "experimentalDecorators": true,
  "emitDecoratorMetadata": true
}
```

These enable the `@injectable()` / `@inject()` decorators and the type-aware metadata emission that Inversify uses for auto-wiring.

**Why emitDecoratorMetadata is required:** Inversify resolves constructor parameters at runtime via `Reflect.getMetadata("design:paramtypes", …)`. Without `emitDecoratorMetadata: true`, the TypeScript compiler does not emit this metadata, so `@inject(TYPES.X)` is required on every parameter. With it, Inversify can auto-resolve when the parameter's type is registered in the container — but we still use explicit `@inject()` for clarity and because the parameter types are interfaces (erased at runtime), so metadata alone is insufficient. `emitDecoratorMetadata` is still good practice for type introspection tooling.

## Step 3 — DI identifiers (`src/di/identifiers.ts`)

```typescript
export const TYPES = {
  // Database
  Database: Symbol.for("Database"),

  // Repository layer
  ICompanyRepository: Symbol.for("ICompanyRepository"),

  // Service layer
  ICompanyService: Symbol.for("ICompanyService"),
} as const;
```

Symbols are used instead of string literals because they are guaranteed unique and avoid collisions if another module registers a binding with the same string.

`Symbol.for()` (global registry) is used over `Symbol()` so that across hot-reload boundaries (Bun `--hot`) the same symbol identity is preserved — without it, every HMR cycle creates a new symbol and the old bindings are orphaned.

## Step 4 — Container assembly (`src/di/container.ts`)

Import `reflect-metadata` for side effects (must be imported before any Inversify usage), then build the container:

```typescript
import "reflect-metadata";
import { Container } from "inversify";
import { drizzle, NodePgDatabase } from "drizzle-orm/node-postgres";
import { TYPES } from "./identifiers";
import { ICompanyRepository } from "../modules/companies/interfaces/ICompanyRepository";
import { CompanyRepository } from "../modules/companies/company.repository";
import { ICompanyService } from "../modules/companies/interfaces/ICompanyService";
import { CompanyService } from "../modules/companies/company.service";
import { CompanyController } from "../modules/companies/company.controller";

const container = new Container();

// Database — concrete instance, no interface
container.bind<NodePgDatabase>(TYPES.Database).toConstantValue(
  drizzle({ connection: process.env.DATABASE_URL!, casing: "snake_case" }),
);

// Repository
container.bind<ICompanyRepository>(TYPES.ICompanyRepository).to(CompanyRepository);

// Service
container.bind<ICompanyService>(TYPES.ICompanyService).to(CompanyService);

// Controller (no interface — concrete class injection)
container.bind(CompanyController).toSelf();

export { container };
```

**Binding choice rationale:**
- **Database (`toConstantValue`):** Singleton, already initialized once. A new instance per request has no benefit and wastes a connection pool.
- **Repository (`to`):** Default scope (transient in Inversify = new instance per resolve). Acceptable because the repository is stateless and cheap. Could use `inSingletonScope()` for marginal GC improvement — not worth it unless profiling shows otherwise.
- **Service (`to`):** Same as repository — stateless.
- **Controller (`toSelf`):** Shorthand for `bind(CompanyController).to(CompanyController)`. The controller is resolved once at startup (for route registration), so scope is irrelevant.

**Why `NodePgDatabase` type from drizzle-orm:** This is the actual type returned by `drizzle()`. Binding it under `TYPES.Database` allows any downstream consumer (future repositories) to inject the same db instance by the same symbol.

## Step 5 — Type definitions

### `src/modules/companies/dtos/company.dto.ts`

Exported interface representing the shape returned to the client:

```typescript
// Fields mirror the DB query output but are explicitly declared
// to decouple the API contract from the DB schema shape.
// Drizzle snake_case casing translates to camelCase in query results,
// so property names here use camelCase.
export interface CompanyResponseDto {
  id: string;
  countryId: string | null;
  name: string | null;
  nameShort: string | null;
  type: "GROUP" | "CLIENT" | "SUBCON" | null;
  haveWorkerEmployee: boolean | null;
  isLdap: boolean | null;
  stsActive: boolean | null;
  createdAt: Date;
  createdBy: string | null;
  updatedAt: Date | null;
  updatedBy: string | null;
  deletedAt: Date | null;
}
```

**Design note:** This is the raw entity projection. If the requirement later demands computed fields (e.g. `countryName` from a join), the service layer adds them as new properties on the DTO rather than modifying the repository.

### Response wrapper shape (used in controller)

```typescript
// Generic envelope for all API responses
interface ApiResponse<T> {
  success: true;
  data: T;
  message: string;
}
```

Returned as `c.json(payload)` by the controller. No separate type file needed for such a small generic — defined inline in the controller or a shared `src/common/api-response.ts` if reused.

## Step 6 — Repository layer

### Interface: `src/modules/companies/interfaces/ICompanyRepository.ts`

```typescript
import type { CompanyResponseDto } from "../dtos/company.dto";

export interface ICompanyRepository {
  findAll(): Promise<CompanyResponseDto[]>;
}
```

**Minimal surface area:** Currently only `findAll` is needed. Adding unused CRUD methods (findById, create, update, delete) before they are called violates YAGNI. They are trivially appended when the corresponding endpoints are specified.

### Implementation: `src/modules/companies/company.repository.ts`

```typescript
import { injectable, inject } from "inversify";
import type { NodePgDatabase } from "drizzle-orm/node-postgres";
import { eq } from "drizzle-orm";
import { TYPES } from "../../di/identifiers";
import { ICompanyRepository } from "./interfaces/ICompanyRepository";
import { companies } from "../../db/schema/companies";
import type { CompanyResponseDto } from "./dtos/company.dto";

@injectable()
export class CompanyRepository implements ICompanyRepository {
  constructor(
    @inject(TYPES.Database) private readonly db: NodePgDatabase,
  ) {}

  async findAll(): Promise<CompanyResponseDto[]> {
    const rows = await this.db
      .select()
      .from(companies)
      .where(eq(companies.stsActive, true))
      .orderBy(companies.name);

    // Drizzle returns rows that structurally match CompanyResponseDto
    // (snake_case casing → camelCase, so property names align).
    // The cast documents the contract without a full map call.
    return rows as CompanyResponseDto[];
  }
}
```

**Why `.stsActive` filter:** Soft-delete pattern (`deletedAt` is part of `defaultColumn`). A non-null `deletedAt` means the record is logically deleted. In practice, coupling this to `stsActive` covers the common case: active = stsActive is true AND deletedAt is null. The repository is the right place for universal query filters.

### SQL generated

```sql
SELECT * FROM "companies"
WHERE "sts_active" = true
ORDER BY "name";
```

## Step 7 — Service layer

### Interface: `src/modules/companies/interfaces/ICompanyService.ts`

```typescript
import type { CompanyResponseDto } from "../dtos/company.dto";

export interface ICompanyService {
  findAll(): Promise<CompanyResponseDto[]>;
}
```

Mirrors the repository interface. The service is a pass-through now, but the interface exists so a future cross-cutting concern (caching, authorization filtering, audit logging) can be added at the service boundary without changing the controller or repository.

### Implementation: `src/modules/companies/company.service.ts`

```typescript
import { injectable, inject } from "inversify";
import { TYPES } from "../../di/identifiers";
import { ICompanyService } from "./interfaces/ICompanyService";
import { ICompanyRepository } from "./interfaces/ICompanyRepository";
import type { CompanyResponseDto } from "./dtos/company.dto";

@injectable()
export class CompanyService implements ICompanyService {
  constructor(
    @inject(TYPES.ICompanyRepository) private readonly repository: ICompanyRepository,
  ) {}

  async findAll(): Promise<CompanyResponseDto[]> {
    // Currently a pass-through. Future additions:
    // - Tenant-scoped filtering (inject org context)
    // - Cache check (inject cache client)
    // - Post-processing (enrich with computed fields)
    return this.repository.findAll();
  }
}
```

**Future-proofing:** Every injected dependency enters through the constructor. When caching is added, the service gets a `@inject(TYPES.CacheClient) private readonly cache` parameter. No signature changes ripple outward.

## Step 8 — Controller layer

### `src/modules/companies/company.controller.ts`

```typescript
import { injectable, inject } from "inversify";
import type { Context } from "hono";
import { TYPES } from "../../di/identifiers";
import { ICompanyService } from "./interfaces/ICompanyService";

@injectable()
export class CompanyController {
  constructor(
    @inject(TYPES.ICompanyService) private readonly service: ICompanyService,
  ) {}

  findAll() {
    return async (c: Context) => {
      const companies = await this.service.findAll();

      return c.json({
        success: true,
        data: companies,
        message: "Companies retrieved successfully",
      });
    };
  }
}
```

**Why `findAll()` returns a closure, not a method:** Hono handlers receive a `Context` argument. If `findAll` were a regular method, it would be written as `app.get("/companies", (c) => controller.findAll(c))`. The closure pattern `controller.findAll()` returns a configured handler with the service already captured, making the route registration simpler: `app.get("/companies", controller.findAll())`. This also eliminates the need to `.bind(controller)` for `this` preservation.

## Step 9 — Route registration (`src/modules/companies/company.routes.ts`)

```typescript
import type { Hono } from "hono";
import { container } from "../../di/container";
import { CompanyController } from "./company.controller";

export function registerCompanyRoutes(app: Hono): void {
  const controller = container.get(CompanyController);

  app.get("/companies", controller.findAll());
}
```

**Why resolve the controller here rather than in `index.ts`:** The `container.get()` call is co-located with the route binding it uses. This keeps `index.ts` clean: only import the register function and call it. Each module owns its route registration.

## Step 10 — Wire into `src/index.ts`

```typescript
import "reflect-metadata";
import { Hono } from "hono";
import { DateTime } from "luxon";
import { registerCompanyRoutes } from "./modules/companies/company.routes";

const app = new Hono();

app.get("/health", (c) => {
  return c.json({
    status: "oke",
    timestamp: DateTime.now().setZone("Asia/Jakarta").toISO(),
    service: "employee-service",
  });
});

app.get("/", (c) => {
  return c.text("Hello Hono!");
});

// Register domain routes
registerCompanyRoutes(app);

export default app;
```

**What changed:**
- Removed raw `drizzle(process.env.DATABASE_URL!)` — the database instance is now owned by the DI container.
- Added `import "reflect-metadata"` before any Hono/app code.
- Added the company routes registration call.
- The `/health` endpoint still works unmodified — it uses `luxon`, not the database.

**Why `import "reflect-metadata"` is at the top of `src/index.ts` and not in `container.ts`:** It acts as a side-effect import and MUST execute before any class decorated with `@injectable()` is evaluated. Putting it in `container.ts` also works, but importing it at the entry point makes the dependency explicit and prevents a classloaded-before-polyfill scenario when the container module is lazily imported by another module. The `container.ts` file also re-imports it (harmless — `reflect-metadata` is idempotent), so it works either way. Putting it in `index.ts` is the defensive default.

## Error handling strategy

The current scope returns a `200` with an empty `data: []` if no companies exist or all are soft-deleted. No explicit error branch is needed at this layer — if the database connection fails, Drizzle throws, and Hono's default error middleware returns a 500. A future task can add a global error handler middleware.
