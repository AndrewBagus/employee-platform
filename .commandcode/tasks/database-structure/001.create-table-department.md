# Plan: Create departments Table

## Main Objective

Create a new `departments` table schema in the employee-service database.

## Context

- Follow existing patterns from `companies.ts` and `countries.ts`
- All tables use UUIDv7 PKs, spread `...defaultColumn`, and snake_case (auto-applied)
- FK from `departments.companyId` → `companies.id` with ON DELETE RESTRICT

## Schema Design

### departments table
| Column | Type | Notes |
|--------|------|-------|
| id | uuid PK | UUIDv7 via `randomUUIDv7()` |
| companyId | uuid FK | References companies(id), ON DELETE RESTRICT |
| name | varchar(100) | Department name, NOT NULL |
| + defaultColumn | | Audit/soft-delete columns |

## Step-by-Step Instructions

### Step 1: Read reference files

Read these files to understand the existing patterns:

```
src/db/schema/companies.ts
src/db/utils/default-columns.ts
```

Study how `companies.ts`:
- Imports from `drizzle-orm/pg-core`
- Uses `randomUUIDv7()` from `bun` for PKs
- References another table with FK (`countries.id` → `companies.countryId`)
- Spreads `...defaultColumn` from `../utils/default-columns`
- Exports the table as a named export

Study `default-columns.ts`:
- Understands what columns `...defaultColumn` provides
- No changes needed to this file

### Step 2: Create the schema file

Create a new file at:
```
src/db/schema/departments.ts
```

**File structure** (follow `companies.ts` pattern exactly):

1. **Imports** at the top:
   - `{ randomUUIDv7 }` from `"bun"`
   - `{ pgTable, uuid, varchar }` from `"drizzle-orm/pg-core"` — note: no `boolean`, `pgEnum` needed unless you add enum columns
   - `{ defaultColumn }` from `"../utils/default-columns"`
   - `{ companies }` from `"./companies"`

2. **Define and export** `departments` table using `pgTable("departments", { ... })`

3. **Columns**:
   - `id`: `uuid().primaryKey().$defaultFn(() => randomUUIDv7())` — exact same pattern as `companies.ts`
   - `companyId`: `uuid().references(() => companies.id, { onDelete: "restrict" })` — FK to companies, RESTRICT on delete
   - `name`: `varchar({ length: 100 })` — department name field
   - `...defaultColumn` — spread the shared audit/soft-delete columns

**Do NOT add**:
- Extra columns not specified (no description, no code, no type enum)
- Any modifications to `default-columns.ts`
- Any imports not needed

**Output format**: Follow the exact same structure and style as `companies.ts`:
- Import block at top
- Table definition with export
- Consistent formatting (indentation, spacing)

### Step 3: Generate the migration

Run the migration generation command:
```sh
bun run generate
```

This will create a new SQL migration file at:
```
src/db/migrations/<next-number>_create_departments_table.sql
```

**Verify the generated SQL**:
- Check the file was created
- Verify it contains `CREATE TABLE "departments"` with correct columns
- Verify the FK constraint references `"companies"("id")` with ON DELETE RESTRICT
- Verify snake_case casing is applied (e.g., `company_id`, `sts_active`, `created_at`)

### Step 4: Apply the migration

Run:
```sh
bun run migrate
```

This executes the generated SQL against the database. Verify:
- No errors during migration
- The departments table exists in the database

### Step 5: Verify

1. Start the dev server:
   ```sh
   bun run dev
   ```

2. Open Drizzle Studio to visually confirm the table:
   ```sh
   bun run studio
   ```

3. Confirm the table appears with all expected columns in the studio UI.

### Step 6: Commit

Once verified, commit the changes:
```sh
git add src/db/schema/departments.ts src/db/migrations/
```

Use a conventional commit message:
```
feat(db): add departments table with FK to companies
```

Also commit the taste folder if it has changes:
```sh
git add .commandcode/taste/
```
